# Hindsight Memory Evidence Runtime B+ SPEC

- **版本**：1.0
- **日期**：2026-08-30
- **状态**：已获用户授权实施
- **目标**：让 Hindsight 在关闭 Agent 原生长期 Memory 后，仍能以可验证的方式提供不低于原生 Memory 的跨会话、跨项目记忆能力。

## 1. 决策

保留官方 Hindsight Bank 作为唯一原始证据库；不新建第二个主记忆库。重构 Bank 之上的查询编排、命题裁决、覆盖验证和同轮交付层，统称为 **Memory Evidence Runtime（MER）**。

本 SPEC 与 `HINDSIGHT-THREE-WAY-RECALL-VALIDATION-AND-REPAIR-SPEC-2026-08-30.md` 分工明确：本文件定义建设方式，三路SPEC定义验收方式。

## 2. 不变量

1. 原始事实、经历、观察、心智模型、实体、图谱和星座仍存于 Hindsight Bank；派生数据必须保留原始 Bank ID 和来源。
2. 不以固定条数、固定 Token、题目字符串、记录 ID 或关键词表决定完成。
3. 相关命题可以大量进入本轮上下文；重复记录必须被压缩为一个命题及其证据集。
4. 后台迟到结果不得被显示为已经进入当前回答；只有 Hook 包或同轮工具结果才算本轮可用。
5. 当前用户纠正、当前附件和当前项目权威来源优先；历史问题保留被替代状态及其替代关系。
6. 图谱和星座必须作为真实候选来源并留下使用或拒绝回执，不能只存在于界面。

## 3. 运行时模型

```text
Adapter -> Query Contract -> Retrieval Session -> Claim Ledger
        -> Coverage Gate -> Context Pack -> Hook / 同轮工具 -> Answer Audit
```

### 3.1 Query Contract

每题产生唯一 `execution_id`，并包含：任务意图、时间范围、规范实体、所需命题槽位、来源权威、允许历史范围、风险等级和上下文预算。确定性规则负责来源、权限和安全；模型规划可补充语义意图。两者不一致时扩大检索，不降级为单点检索。

### 3.2 Retrieval Session

每个会话至少支持：语义、关键词/别名、时间、类型、图谱、星座、来源和预计算 Dossier。每条候选记录：通道、查询、页码、关系路径、得分、耗时、原始 Bank ID。检索继续到所有必需命题有证据，或连续两轮扩展没有新增必需命题。

### 3.3 Claim Ledger

候选先归并为原子命题，而不是直接按记录打分。每条命题拥有：陈述、时间有效区间、当前/历史状态、规范实体、关系、权威来源、原始证据、替代/冲突关系、必需性和准入状态。

### 3.4 Coverage Gate

仅当问题契约所列命题槽位、必要实体关系、时间阶段和来源证据都被覆盖，且完整性挑战收敛时，才返回 `complete`。否则返回 `incomplete`、`best_effort` 或 `bank_absent`，并提供可继续调用的扩展计划。

### 3.5 双交付

- 简单问题：Hook 在短时内交付完整首包。
- 历史演进、开放盘点、跨任务接管、来源核查和关联闭包问题：Hook 在当前 Codex 可配置时限内进行覆盖型预检，不在没有覆盖回执时错误声明完成。
- Agent 推理中发现缺口：调用同轮 `expand`、`timeline`、`graph`、`source` 工具；工具结果进入本轮上下文。

关键覆盖不能仅依赖 Agent 自觉调用工具。后台延续只能服务后续请求，不能计为当前轮注入。

## 4. 预计算记忆产品

派生层包含并版本化以下产品：

- `Task Capsule`：任务当前状态、权威文件、决定和未完成项；
- `Topic Dossier`：长期主题的阶段目录和证据锚点；
- `Timeline Index`：阶段、转折、有效期和替代关系；
- `Entity Dossier`：规范名、批准别名、关系和证据；
- `Policy/Profile Snapshot`：稳定偏好和规则；
- `Core Context Capsule`：跨 Agent 的最小稳定协作上下文。

派生产品是加速索引，不是独立真相；失效、冲突或原始证据变化时必须重建，并可回到原始证据。

## 5. 图谱与实体

图谱检索优先使用规范实体 ID 和已命中的 Bank ID；不得把前三个通用短语当作唯一图种子。星座关系必须输出路径和对本题的命题贡献。相似名称仅进入别名候选队列，只有证据充分的别名才自动折叠。

## 6. 9998 可解释性

每条执行记录必须显示：Query Contract、命题槽位、各检索通道、图谱/星座路径、候选记录数、去重后命题数、准入/拒绝理由、Hook 注入、同轮工具补充、答案使用/未知、尚缺覆盖和耗时。任何 0 注入必须明确属于合理不需、当前来源覆盖、候选拒绝、预算延后、超时或故障之一。

## 7. 验收与迁移

1. 先以影子方式运行 MER，对照原生产链路，保留可一键回退。
2. 使用三路差分SPEC：A（上下文/原生Memory）、B（Bank Exhaustive）、C（真实生产注入）和 C-answer（Hindsight-only）。
3. 所有题以命题召回、命题精度、关系闭包、时间/来源正确性、回答对齐和链路一致性验收。
4. 同题修复后必须运行改写题、迁移题、负例和封存题；不得以服务健康或关键词命中替代验收。
5. 只在验收集满足门槛后，将 Codex/Hermes Adapter 从 shadow 切至 enforce；原生 `MEMORY.md` 保留为对照，经过 Hindsight-only 回归后再退出主链路。

## 8. 明确不做

- 不全局提高 Token 或超时；
- 不让 Qwen 替代全部检索通道；
- 不注入全部原始记录；
- 不接入第二套主记忆引擎；
- 不把模型生成答案重新当作独立事实；
- 不把后台结果伪装为当前轮可用记忆。

## 9. 运行期回执完整性（2026-08-31 补充）

1. **零注入也必须是完整 Hook 响应。** 当前文件优先、当前工作集足够、无相关记忆、召回超时等分支都返回标准 `hookSpecificOutput` JSON，并写入同一 `query_id` 的注入回执；绝不以空 stdout 伪装为“没有问题”。
2. **来源优先仅限真正的当前权威事实。** “备份保留/恢复演练/来源核验”等历史规则盘点不能因含有 `WPS 云盘`、`云端` 或平台名而被误判为当前同步状态；反之，明确询问“现在 WPS 同步是否完成”的问题必须保留当前来源边界。
3. **状态页不能因日志变大而遗失真相。** 追加式 `query-controller.jsonl` 与 `memory-effectiveness.jsonl` 分别是链路和回执的唯一事实来源；同时维护两个按 `execution_id` 键控、仅供最近可见执行读取的有界投影（trace 与回执）。9998 先读轻量尾部和投影，投影缺失才做有界补读。两者都不参与检索、排序、注入或回答。
4. **后台 continuation 永远是同一用户回合的辅助执行。** 9998 按不可变的用户问题 fingerprint 合并显示，主卡选择实际 Hook 投递最多的已完成执行；辅助执行的 id 与结果仍可审计，但不得显示成第二条“0 注入用户对话”。
5. **验证必须在日志压力后复核。** 每次真实等价回放后，除比较 Hook 回执和 9998 初次结果外，还要在后续多题/多反馈写入后再次核验可见 trace；否则只能证明瞬时一致，不能证明用户稍后刷新仍一致。
