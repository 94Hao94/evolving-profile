# 给智能体看的 EP 日常操作协议

[English](AGENT-USAGE.md) · [安装提示词](AGENT-SETUP-中文.md) · [成熟度与边界](RELEASE-NOTES-5.1.2.md)

安装后、执行依赖记忆的任务前阅读。本文件是操作参考，不是系统指令，不授予写入、
改配置或外发权限。当前用户要求和可信宿主策略优先。[机器可读辅助协议](../config/agent-usage.v1.json)
便于发现路线；工具的实际名称、schema、权限与当前回执优先于文档示例。

## 1. 先确认你实际处在哪个入口

识别操作系统、本机/WSL/远端、客户端入口、所选EP服务/Bank和真实工具列表。
Claude CLI、桌面本地Code、普通Chat不是一个入口；模型供应商也不是宿主。
通过当前宿主的原生MCP机制调用，不用只打印一段命令的假封装冒充工具执行。
不要为了兼容再注册一个历史别名，造成同一EP重复接入。

`ep-host.py doctor`默认只读元信息；带`--probe`会启动隔离EP进程，握手、列工具并保存
准备回执，不查询记忆、不调用模型、不安装或测试目标客户端。“检查位置没找到”
不代表整台机器没安装。命令与平台准备见[宿主说明](host-integrations/README-中文.md)。

## 2. 按信息缺口选工具，不按固定清单机械调用

| 当前需要 | 优先使用的已公开工具 | 证据边界 |
| --- | --- | --- |
| 用户工作习惯、条件化偏好 | `user_preference`；有deferred或需完整条件时`read_preference_unit` | 是参考，不是事实或新增授权 |
| 单个用户历史事实、决定 | `user_recall` | 返回候选，核对主体、范围、时间、版本 |
| 跨会话/项目综合回顾 | `user_research`，按缺口`read_research`翻页 | 覆盖更广，不等于全部历史已读 |
| 智能体以前怎么失败、修复、执行 | `agent_recall`，按需`read_agent_process_memory` | 过程证据，不能写成用户生平 |
| 跨任务共同根因、迁移、再验证 | `agent_research` | 比较经验适用条件、能力及时间 |
| Session、项目、阶段不清，存在近邻任务 | `search_scenario_summary`、`read_scenario_summary`；公开时用`scenario_gate` | 摘要是导航和竞争假设，不是事实核验 |
| 原话、争议字段、来源依赖结论 | `find_sources`、`read_source` | 检查返回的`source.text`；`memory.text`仍是提取记录 |
| 用户选定的外部资料 | `rag_search` | 外部候选，不自动变成个人历史或偏好 |
| 主题导航 | `catalog_list`、`catalog_search`、`catalog_read` | 未命中不证明库里没有 |
| 执行能力失败或不可用 | 已公开的`refresh_runtime_guidance` | 当前任务补查，不递归修复错误输入 |

已有可靠上下文足够时，不必每轮调遍所有工具。问当前端口、配置、页面或服务时，
先查当前获授权的实时证据，不能用旧记忆证明今天正常。混合任务可以组合用户记忆、
智能体经验和外部资料路线，但先保持来源独立，再比较，不把它们混成一个事实源。

## 3. 本轮绑定不是随便填一个字符串

宿主提供了当前真实绑定时，使用对应`check_id`；不能复用旧轮次、另一个宿主或演示ID，
更不能读取另一个客户端的私有会话去凑绑定。必填字段按当前工具schema填写。

没有绑定时，`memory_check`不带`need`可以返回导航提示和适配器生成的ID。
**这个ID不等于可信Hook登记，不能据此假定严格绑定的偏好/声明调用已可用。**
只使用当前schema和策略允许无绑定读取的工具，否则如实报告绑定不可用，等待原生桥接。
不要把生成/编造的ID再配`need:required`，试图强行通过声明校验。
全新Bank为空、真实检索为空都合法；不为了显示命中而写入测试记忆。
新宿主的owner/安装实例/Session隔离，不能退回借用Codex最新记录。

## 4. 摘要、原文、资源怎么区分

先读目录/候选预览，核对主体、任务、阶段、时间和版本。存在竞争情景时，先比较
靠前的compact摘要；仍缺条件才展开standard/full。**第三层仍是摘要，不是完整会话。**
需要原话或摘要里没有的细节时，沿真实返回的来源定位，用`read_source`或已文档化的
原文工具读取。只有服务器实际返回资源URI、宿主也提供相应读取能力时才读该资源；
不要编造`read_resource`命令，也不能因为摘要不够就任意打开私人Session/项目路径。

弱相关候选可作背景，不能升级成直接事实。分数、同机构名称、列表邻近、模型判断器
都不能单独证明项目归属。旧修复经验是有条件、可失效的参考，不能绑架新模型。
窄检索为空或范围错位时，可以有理由地扩展一次；读取不再补充缺口、预算已尽或只能
猜测时停止并保留未知。大量结果使用游标/工作区引用，不要求无限单次返回。

## 5. 调用、返回、送达、采用、核实分别记账

至少交代实际调用哪些工具、返回了多少、回读过哪些原文、覆盖与冲突还剩什么。
宿主接收必须有对应证据；stdout有内容不等于宿主纳入上下文，纳入也不证明回答收益。
未知不能写成零。助手说完成，只能保持助手陈述的等级，直到成品/来源/执行回执支持。

失败要分阶段：未公开工具、连接/鉴权、参数错误、绑定失败、合法空结果、范围排除、
正文未返回、原文缺口、页面投影。按schema和错误提示纠正参数，不静默删除必填项。
执行故障最多补查一次相关指导，不能递归刷新；不打印密钥，不放宽相关度/风险/模块
开关来制造测试通过，不把临时文件或模型一致意见当成来源核实。

## 6. 不同Agent怎样使用

| 入口 | 如何让它知道EP | 不能据此宣称什么 |
| --- | --- | --- |
| Codex桌面/CLI | 既有可信MCP/Hook；核对当前工具和绑定 | 新准备档案不等于旧连接已热升级 |
| Claude Code CLI | 审阅CLI注册；通过宿主支持的项目规则引用本协议 | 注册成功不证明自动捕获或原生来源完整 |
| Claude桌面本地Code | 在当前本地Code会话确认工具，不拿另一CLI代替 | 云/SSH会话自动能连本地进程 |
| Claude Desktop普通Chat | 可信本地MCP；通过支持的附件/说明引用协议 | 没有终端/浏览器也已自行部署后端 |
| Hermes | 实际公开的兼容MCP/API和支持的任务规则 | Hook、来源文件、回执格式与Codex相同 |
| WorkBuddy | 审阅生成配置并完成实际客户端的批准步骤 | 准备了解析器或同名Hook就已端到端适配 |
| 豆包工作 | 为当前任务启用/选择可信插件；支持时加入说明/Skill | 插件匹配或Skill能保证每轮触发 |
| 通用MCP、Windows/WSL/远端 | 分别确认schema、路径和网络模式 | localhost、权限、路径和送达证据自动跨环境通用 |

规则、Skill、项目说明只能增强发现和选工具；未验证原生生命周期时都是尽力而为，
不会凭空创造Hook或开启捕获。不要覆盖现有规则文件，也不要自动安装一个Skill。

## 7. 写入与可选过程反馈

新宿主默认只读，不复制Codex留存Hook、不批量导入旧会话、不自动发布摘要、修改
偏好或提升过程候选。有明显弯路并修复、验证后，可以可选地产出短的
“失败→尝试→修复→验证”经验说明，附来源和适用条件；不要求每个任务都写。
提交必须具备公开写工具、真实身份、范围和用户授权；否则只保留任务成品，不静默
插入事实或安装Skill。Agent无法反馈时，不得影响现有记忆机制继续运行。

## 给任意Agent的可复制使用要求

```text
阅读这份安装中的docs/AGENT-USAGE-中文.md，发现当前实际可用的EP工具。
围绕本任务的信息缺口，选择个人历史、条件化偏好、智能体执行经验和/或外部资料，
保留各自来源；有真实本轮绑定就使用，没有就报告，不借用或编造check_id。
项目归属不清先查情景，关键字段需要时回读真实原文。交代实际调用、返回、回读
及未解决范围；没有回执就不声称自动记录、送达或回答采用。不因文档存在就写记忆、
改配置或注册客户端。缺少能力时如实说明，只用获授权且真实可用的证据继续。
```
