# EP5.1 固定来源选择与严格关系输出设计

状态：用户已认可协议级方向并要求开工；沿用其自审、连续执行、最后独立复核的授权。本文自审后进入实施，不重问执行方式。日常仍 source_shadow / model_trial=false / segment_coverage.v1。

## 1. 目标与非目标

解决真实回执中三类失败：提取器重抄引文漏字、关系器混淆意图与来源页及单条/关系对、把外部成果未核验误作历史记录不忠实。程序负责精确来源与结构；模型负责含义、意图和有证据的关系。

不改 Provider、模型、密钥、日常模式、风险/JEV/RAG，不重置旧作业、不自动恢复生产、不发布 GitHub。没有固定学校、文件名、语言关键词的放行。声明范围审查不等于穷举关系、事实真实或用户任务成功。

## 2. 方案取舍

- 继续自由引用＋提示词：兼容但继续要求模型抄长路径、数位置，实测不稳；不选。
- 按标点固定拆一个意图：机械但会拆断条件，也无法表示一句多个要求；不选。
- 固定原文卡＋可共享来源的版本化意图＋严格类型关系：选用。卡片不是意图；多意图可以引用同一卡，须独立语义复核。

## 3. 范围和版本

现有 hierarchical_review.v1 增加内部 wire_contract=source-selection.v2；保持现有业务接受轴与默认选择不变。请求绑定显式携带 wire_contract，完整协议指纹纳入配置和新代码。旧 direct 调用未声明 wire_contract 时仍走旧表示，不把旧回执解释成新回执；真实分层任务由宿主 review_binding 指定新表示。

缓存、增量重绑及资格必须同时核对协议指纹和 wire_contract。旧请求/响应、拒绝、尝试和预算原样保留，不搬动旧结果洗绿；无新资格不进入日常辅助运行。

## 4. 固定来源卡

卡绑定当前请求的 primary span，含角色、顺序、原文及窗口完整性边界。使用带类型的短别名：s=primary span/card，i=用户意图，z=残余，a=助手报告，o=义务，p=原文页，c=上下文页。别名只在一个请求有效，不是永久记忆 ID。

原文在模型窗口只放一份；primary 可引用卡，不在每个提案内重复全文。默认每个现有运输 span 一张卡，不用标点强制划定语义任务。一句话有多个要求时，可以形成多个候选意图共享卡；一个意图跨卡时可选多卡。所有原文和 Unicode 位置由宿主展开，模型不写 quote/start/end，不接收任意路径。

没有可见正文的运输记录留在原始覆盖账本，但不进入可选卡、模型 primary 或模型阅读 ID 目录；不能要求模型“读到”未展示的空别名。映射反馈先按同一选择契约逐条展开，再检查规范来源，不把新格式的 source_cards 误当旧格式缺少 source_refs。

提取响应声明 wire_schema=source-selection.v2，保留 proposal.atoms/residuals/assistant_claims 三平面。每项 source_cards 是本次 s 类别名数组，语义字段仍完整保留动作、条件、否定、例外、时间、对象假设。禁止混入 source_refs、quote、伪造 host 证明；空/重复/未知/错误类别卡拒绝。不同角色卡不可混作同一平面权威。

提取器只提案，不自审。结构映射错误至多一次现有有界修正；原始响应和错误留档，所有调用走同一预算。语义否决不以格式修正重试。修正后仍有错误保持缺口，不补造遗漏含义。

## 5. 来源身份与语义身份分开

旧 source_offsets.v1 的默认 ID 与重复检查保持原义。新 source_semantics.v2 由宿主显式选择：source_group_id 绑定范围、Session、原始来源/角色/位置；stable_id 再绑定规范语义提案字段及种类，不信任模型提交的 ID 或身份版本。

同来源不同语义可以是两个候选；同来源同语义重复仍拒绝。共享来源不重复计算字符覆盖。语义 ID 不宣称跨模型同义稳定；语义改写可能形成新修订，至少使相应目标/祖先复核失效。精确缓存复用要求原文、语义、权限及协议皆未变。

独立叶审仍需检查是否漏掉独立动作/条件。卡全部被选中只证明结构覆盖，不能证明意图完整。无来源的虚构意图、有来源但扭曲否定/主体、粗粒度遗漏都不能靠完整字符覆盖通过。

## 6. 严格关系输出

merge/readback 继续返回现有判断头和 read_ids，但数据输出使用 relations、record_obligations、states，禁止与旧 object_links/group_states/obligations 混用。

- relations 每条必须 kind、from、to、sources、state、reason；kind 仅 same_object/responds_to/corrects/supersedes/contradicts。两端是当前 i/z/a 类目录中的不同记录，不能用单个 item 代替关系对。sources 只选择本次实际回读的 p 类页。
- record_obligations 每条必须 id、kind、items、sources、state、reason；kind 仅 identity/reference/chronology/condition/correction/response_relation/contradiction。items 非空，state 沿用 open/supported/refuted/not_applicable；终态仍必须有实际原文证据。
- states 每条必须 item、state、sources；状态沿用 current/historical/unresolved/reported。助手报告不能被 state 升级为外部事实。
- 新义务使用注册配置中的独立 `new:` 命名空间；已有义务只能选实际 o 类 ID，未知或错误类别别名不转成新义务。同一响应不得重复 state 目标，即使状态文字相同。
- 关系类型与方向、记录义务类型须经过校验、保存、关系链重建和后续回读全过程保留；已有义务更新不可静默改变类型、端点或方向。
- 不允许模型生成外部成果核验凭据或 host_validated。宿主按固定规则将同对象关系映射到原 object_links、其他关系及义务映射到带类型的既有义务结构；来源卡由宿主填准确引文。原始模型 result 不改写，规范视图按请求确定性重建。

请求封印 reviewed 之前核对所有结构和 ID 类别。旧异常缓存重建仍返回可审计缺口，不抛异常逃逸。未知字段、错误类型、缺端点、错误页、单条假冒关系对都拒绝，不能自动猜端点或换词为合格结构。

## 7. 历史忠实与实际成果

模型的关系义务仅描述记录中的主体、时序、指代、条件、纠正和答复关系。原文写“我完成了备份”只可证明助手这样报告；原文没有备份文件/工具凭据是外部成果限制，不是该历史报告本身有误。

外部成果注释由宿主从已独立审阅的 assistant_claims 角色生成：assistant_report_unverified；不让模型用自由 outcome 分类吞掉真正的身份/条件义务。task_outcome 继续 not_verified，不因记录审查通过变成成功；记录范围仍不清的叶 scope/record_obligations 保持阻断。

模型仍可能把外部核验任务错贴成某种记录义务；必须用真实/反例评测发现，不按 reason 关键词删除义务、不自动把 open 改终态。若此问题仍存在，明确未合格，不通过规则伪造理解。

## 8. 容量、预算、兼容

实际 provider envelope、提取结果后的叶审、原文页和前页状态都计入当前容量；沿用有界输入/输出拆分，不扩大日常限额、不截断卡、不删除未决。提取卡/别名目录自身也必须参与规划。预算继承原隔离总账，所有失败、重试、备用请求均计数。

缓存中的失败分类不作为独立权威：原始响应摘要必须与实际预算回执一致，拒绝原因从原始响应重新计算。被篡改的 reason/status/result 不得触发格式修正、额外付费重试或语义否决绕行。

UI 沿用现有四轴及层级，不新增“任务已完成”的绿标。只读返回可附宿主派生的未核验报告说明；没有前端改动不得声称视觉验收。新字段/状态定义来源于注册配置，中文/英文用户文案不硬编码多份。

## 9. 验收与停止条件

先跑离线 RED→GREEN：中文/英文/emoji/路径、同一卡多个意图、跨卡条件、重复提案、角色冒用、未知卡/页、单条冒充关系、外部成功自述、跨项目、缓存篡改/重绑、真实 wire 超限及原文完整性。

再冻结代码和样本跑实际配置模型：重现旧失败、单变量对照、新自然任务、英文反例。调试样本不叫盲测，合成不算自然样本，模型自评分不算收益。先最小闭环，再决定是否跑两条超长来源；没有独立金标/答案收益仍不能启用新协议。

全量后端/本地发行测试、封装扫描、源/运行目录一致性、服务和默认设置核对；一次最终独立审查及有测试的一轮重要修复。不能因全部测试进程退出而声称所有语义样本通过。

自审结论：已明确共享来源不等于多次覆盖、旧 ID 不被重解释、原始回执与规范视图分开、无模型自由 outcome 豁免。仍未知的是实际模型在严格选择契约下的语义表现，必须实测而非预先承诺。
