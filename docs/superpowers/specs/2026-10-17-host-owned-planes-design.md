# EP5.1 宿主确定角色与记录平面

状态：用户明确要求按前述新分工执行；沿用已授权的自审、连续原生执行和最终一次独立复核。非 Git 源码使用精确基线与隔离验收目录，不伪造提交。

## 目标和边界

移除模型对已知来源角色、记录容器和 authority 的重复决策。不是换模型、调 Recall 准入门槛、放宽语义核验或开启日常辅助模式。默认 source_shadow / model_trial=false / segment_coverage.v1、Provider/Key、生产历史和旧次数保持不变。

## 方案与取舍

继续三容器并强化提示词仍有角色冲突；每个来源角色分开一次提取可隔离，但增加请求并丢失同窗口可见关联；选择单一 items 提案、由宿主按其真实卡片角色确定容器。保持同一窗口一次提取，并让叶审仍看到原始上下文。

## 显式新契约

新增 source-selection.v3，与 v2 显式区分；v2 请求按原三容器规范处理，无声明仍沿用原 literal 路线，未知声明继续拒绝。旧回执不重写、不跨版本重绑。独立 host_plane_wire 注册项保存 schema 与语义分类，现有 selection_wire 保持 v2 定义。

v3 提取 JSON 为 wire_schema、proposal:{items:[]}、context_requests。每项选择实际 source_cards，提供 kind、action、conditions、negation、exceptions、object_hypotheses、time、local_state，可有 claim。模型不得输出 authority、role、plane、来源位置、永久 ID 或三个旧容器。

宿主验证卡片存在、非空、顺序、不重复，且同项所有卡必须来自同一角色。来源 role=user：kind=non_substantive/unclassified 成为相应残余；六类用户语义成为 atoms，claim 对应 user_claim，其他对应 user_requirement。来源 role=assistant：永远进入 assistant_claims；明确 suggestion 对应 assistant_suggestion，其余为 assistant_report，绝不变成用户要求。kind 仍是待审阅语义分类，来源角色不是模型判断。未知来源角色或混合角色选择拒绝，不能猜。

模型提案、宿主规范视图与物理来源保持可区分；host-derived authority 不证明具体含义、外部真实或实际执行成功。助手转述用户要求仍只证明助手这样说。所有记录仍须通过独立叶审。

完整性由宿主检查：v3 的非空 USER 与 ASSISTANT primary 均须被来源范围覆盖，避免模型靠完全不输出助手条目形成空的智能体平面。叶审通过也不能豁免缺失角色覆盖。只需保留非实质助手内容时仍可用相应 speech-act kind，归属始终是助手报告。这个机械覆盖不证明已提炼出可复用经验；v2 和无声明路径的原要求不变。

## 全链路一致性

同一 schema 判断用于实际请求、解析、映射反馈、叶审、缓存与增量重绑。v3 原始 items 的修正反馈逐条展开后检查所有规范平面，不按旧数组或旧 source_refs 格式误判。原文只发送一份；空卡仍保留物理账本但不进入可选/阅读目录。

v3 叶审输入保持宿主重建的三平面规范记录，不要求审查模型再选择 authority。关系输出继续严格端点/来源分类、未决义务和时序核验，仅 header 显式标 v3，不放行 p 页成为记录，不把不确定结果改成支持。缓存必须核对完整原始响应、预算、schema 与请求，不复用 v2 资格。

v3 同时把已知字段域放入实际 Provider 的 JSON Schema 请求：来源卡限于该角色的真实候选，关系端点/状态只允许记录 ID，证据只允许已读原文页 ID。该 schema 是宿主类型约束，不包含源文，不证明模型注意力或语义判断。支持不足/忽略 schema 的服务仍由本地校验拒绝；不得隐藏新增重试或擅自换 Provider。v2/无声明保持原 json_object 请求。schema 允许 defective、unresolved、not_verified，不能用结构约束强制通过。容量必须测量包含该 schema 的实际 HTTP envelope。

同一助手报告与实际已读原文页全文完全相同、角色及来源顺序匹配且唯一时，模型运输视图可以用 reported_statement_pages 引用该页。只在序列化更短时替换；原规范记录、物理来源及原 Provider 响应不变。没有匹配、仅近义、未读或有歧义均保留文字。此机制只消除重复传输，不生成关系、不证明事实，也不提高原输入上限。

## 语义与验收

角色正确只是机械条件，不能补出遗漏的时间、指代、排他、修订或材料范围。提示应说明这些通用维度，但不得按当前样本关键词填内容；仍沿用冻结的独立原文断言，不拿新输出重写标准。

先 TDD 覆盖混合窗口、助手引用用户、双语/emoji、同卡多意图、残余、非法字段/卡/角色、原始回执不变、v2/无声明兼容、映射修正、缓存和重绑。全套后端回归绿后，先一个真实混合来源闭环，检查每阶段原回执再扩大；失败先定位，不排队跑已知有缺陷版本。

真实测试沿用原隔离账本。当前 538 次计数不清零；本轮最多再执行 64 次（总上限 602），Token 总上限仍 3868256。所有失败/修正/备用均计数，串行调用。是否扩展到其余自然样本由最小闭环的证据决定；不能靠同题重复到绿。

最终分别报告机械归属、语义保留、范围/时序、完整流程与回答收益；无资格不启用。代码审查一次并做有 RED→GREEN 的重要修复。源码/运行/本地发行选择性同步、备份、全套回归、脱敏扫描、唯一真相源审计与服务设置检查完成后再交付，不自动发布 GitHub。

自审：明确来源角色与语义 kind 不同、v3 不反向改变 v2、同角色跨卡允许/混合拒绝、助手不因引用用户而改权威；不把宿主元数据当语义证明。现有流程包含完整可复用的规范存储/回读，不建立第二套数据路径。
