# EP5.1 超长会话全局覆盖与来源读取协议设计

状态：用户已于2026-10-16认可设计与实施计划，选择连续执行后统一独立复核；实现状态以验收台账为准。日期：2026-10-16。

## 1. 目标与当前授权

用户要求继续收口EP5.1，保持泛化、增量处理、可见回执、唯一真相源和多语言，不反复依赖人工校准或用户重新出题。当前已授权实施：重启后MCP验收、回合定位定点修复、两个明确旧作业在原预算内恢复；本文件另描述改变全局覆盖信任契约的后续架构。

目标不是“模型从不出错”，而是：任何有界来源都有可检查的覆盖范围；漏项、冲突、过期和不可读不冒充成功；长会话可以持续增量处理，而不反复把全部原文塞入一个请求。

非目标：替换现有用户事实/偏好/智能体记忆/RAG检索；自动升级助手自述为事实；把工作目录当已确认项目；无限重试；修改Provider/密钥或发布GitHub；强行处理禁止写入的来源。

## 2. 当前证据与缺口

- 已有分块草稿和分块/跨块审查，但最终全源覆盖仍受完整请求容量限制，局部分块通过不能代替全局语义审查。
- 两条旧over_budget规范化后约26k/30k语义字符，原预算输入不变；必须沿用已用1次，不因规范化购买新次数。
- 另一条约50k语义字符，原文/原句目录加完整草稿运输曾超过120k序列化字符上限。单纯提高限制不能支持任意增长会话。
- 原始回合定位有压缩格式缺口：实际来源可能只剩.jsonl.zst。缺少解码支持不能标为source_missing；大文件的有界扫描也不能证明目标回合不存在。
- 层级3仍是压缩摘要，不等于全量原文。现有v3逐意图/full字面包含门不可在新实现中悄悄放宽。

## 3. 总体结构

固定来源快照 → 无损来源单元与有界分段 → 分段独立语义复核 → 覆盖/纠正账本 → 跨段冲突审查 → 三级导航与可展开约束 → 原子发布。

结构完整性与语义充分性始终分开。哈希、ID完整和模型同意只能证明各自的检查，不合并成外部事实核验。

### 3.1 来源快照与水位

每次工作冻结source_snapshot_id、来源选择/规范化版本、明确消息水位、顺序、角色、物理来源版本和权限版本。新消息进入下一代快照，不在执行中偷偷扩大输入。更新/截断/权限变化时旧结果不发布到新快照。

范围明确为当前情景源策略所选的可见用户消息与助手最终回复；工具日志、隐藏推理、其他会话不因此成为已读。结构化宿主元数据只按已定义协议排除，记录排除定位/哈希/理由；混合人工文本不能一起丢弃。Agent工具过程证据仍由独立过程链路承载并显式关联。

### 3.2 物理存储与语义身份分离

语义预算身份由有序实际内容、角色及有效知识权限决定。文件压缩、路径搬迁、读取器版本、Provider变化、预览变化或complete/over_budget状态变化不能制造新预算。

物理证明另记录：路径、codec、压缩文件/原始记录哈希、头部Session身份、定位空间与当前可验证状态。改变物理表示后，只有重新解码并证明原消息序列/角色/原始记录哈希等价，才能重绑定定位；不能只看文件名或相同工作目录。

plain_jsonl与zstd_jsonl走统一格式适配接口。压缩源的byte_offset必须标明decompressed_jsonl逻辑空间，不能把解压偏移传给压缩文件seek。未知格式、无解码器、损坏帧、达到读取预算分别报告，不回退到最近一轮冒充指定turn。

索引/缓存只是定位线索。实际回读须验证相应原始记录哈希与角色；zstd索引若不支持可靠随机定位，使用有界流式索引和可续作状态，不一次展开整个大文件到内存。是否落盘物化缓存需要磁盘限额、过期和来源绑定，不默认生成无上限的完整副本。

### 3.3 来源单元与分段

SourceUnit携带message_id、turn_id、角色、顺序、原始记录定位/哈希和语义文本哈希。长消息可分运输span，但span必须覆盖完整消息、按Unicode码点/有效UTF-8边界定位并保留原消息归属；不能把运输切片当新的独立用户意图或跨项目证据。

分段结合任务连续性、实际输入/输出容量和完整条件边界，不按学校、项目专名或固定“每N轮”切割。上下文重叠标为context_only，不重复计算主覆盖、不允许借相邻段的来源补成本段主证据。单条超长条件使用可展开原句span引用，不裁掉否定或后半条件来满足长度。

## 4. 覆盖账本

账本是完整可分页的来源→意图→字段→摘要/原文映射，不是再写一份无来源总摘要。

| 对象 | 必须绑定的信息 |
| --- | --- |
| SourceUnit | snapshot、message/turn、角色、顺序、codec定位、原始及语义哈希 |
| Requirement | 原句/span、kind、所属对象/范围、有效时序、分段主覆盖 |
| LocalReview | 实际检查的SourceUnit/Requirement、草稿指纹、模型/协议版本、逐项判断和缺口 |
| Relation | 同一事项的修正/替代/答复/冲突；两端原文与角色、时序、判断来源 |
| GlobalReview | 账本版本、审查分区与交界、未决冲突、覆盖缺口、接受/拒绝及实际回执 |

每条实质要求必须为covered、由后续用户明确替代的superseded，或显式unresolved/omitted。简单确认只有在没有独立执行要求时才non_substantive。助手建议不能成为用户约束；助手报告“已完成”只能是answered/self_reported，不能证明外部成品成功。

同句在不同会话重复出现不构成同一项目。缺少权威项目关联时保留Session独立账本或workspace_navigation_only，不以相同cwd/机构合并为现行结论。自动证据支持的关联可复核，不设必须人工校准的常规门；无法裁决时保留竞争假设。

## 5. 全局复核的能力与边界

1. 结构审计检查完整来源顺序、span无遗漏、主覆盖不重算、每项映射可还原、角色正确、所有必审单元均有绑定的复核结果。
2. 分段审稿实际读取其声明的完整原文单元，检查意图提炼充分性与条件；不能只比较模型自己生成的两个摘要。
3. 跨段审稿读取完整要求/纠正索引与变化关系，检查远距离纠正、阶段变更、答复限定、冲突和未完成请求；疑点精准回读两端原文与必要前后文。
4. 若账本本身超出请求容量，按明确对象/要求分区审查并记录交界审查。只有审查计划覆盖全部账本分区和相关交界才可声明该计划完成；检索top-k结果不能证明没有其他冲突。
5. 形式覆盖可确定性验证，语义遗漏/替代正确性仍是模型判断。回执必须公开两者状态、覆盖范围和未决项，不宣传绝对语义完备。

分区和交界审查的策略是可版本化的契约，不是“各块accept=true则整体accept=true”的布尔归并。未实现/未审查的交界继续为unknown。不能用一个抽样审稿声明完整全源覆盖。

## 6. 发布与兼容协议

新增segment_coverage.v1信任契约和对应新摘要schema，不重写旧v3含义，不把旧接受回执批量升级。原有完整全源审查路径继续适用于容量内的来源。

旧v3要求某项意图对应的完整字段文字出现在full层。新模式若以可展开账本替代部分逐字正文，必须显式声明full_is_navigation_with_coverage_links，不称为原v3全字面覆盖。关键当前条件必须在导航中突出；未展开部分通过coverage_cursor/Requirement ID按需读取，返回has_unread_requirements/requires_readback/未覆盖范围，不能把未展开当不存在。

read_scenario_summary保留原调用兼容；新schema下可增量读取摘要、特定要求及来源定位，分页游标绑定snapshot/账本版本/过滤条件。任何来源修订变化令旧游标明确失效。源文回读与摘要导航使用不同证据标志，过程ID不能传给用户Bank的read_source。

发布条件：快照仍当前、权限与范围有效、结构审计通过、该契约规定的分段及全局语义审查接受、所有强制缺口已处理。外部事实/正式文件仍不由情景摘要核验。有未决项可发布清楚标记的局部导航，但不能写overall_complete或覆盖替换此前更可靠的全量版本。

后台数据、可观测回执和Web共用一个状态/schema注册源。新契约先shadow，不注入、不阻止旧正确路径；通过真实源和反例对照后才按配置切到assisted/enforced。不存在绕过权限/原文哈希/语义拒绝的“强制成功”选项。

## 7. 增量与断点

分段缓存必须绑定精确SourceUnit集合、草稿与审查契约/Provider模型版本、权限及范围。未审核草稿与接受回执分层存储。失败、崩溃或换模型不能把一个层级的缓存提升成另一个层级的通过。

新增尾部消息只重建受影响分段；但最终当前状态及跨段纠正关联必须重审，不能因为旧分段未变而跳过新增纠正对远处内容的影响。修改/删除旧消息使其所在段、引用边和依赖的全局结果失效。新候选按独立版本保存，拒绝保留，不覆盖为accept。

并发写回采用精确snapshot/权限版本及CAS，单一生成只允许一次结算。中断后可从已完成的相同阶段继续，但每个必须核验的门仍执行；输入和版本不同不能借用旧accept。

## 8. 预算与模型适配

沿用已花费作业预算并建立分阶段Token/请求计账；每个Provider请求先预留再结算，超时未知用量单列，不伪装零。细分段、改变格式、重启或更换模型不能重置父作业额度。失败只重做受影响阶段，不全历史反复提炼。

实际容量来自当前配置与能力探测，不用“强/弱模型”固定名单或模型名称推断可靠性。采用可回滚的运行观测决定请求大小/抽取复杂度；更优秀的新模型可以减少冗余提示或合并可承载工作，但不绕过独立来源验证。中文、英文、代码与长原句分别按实际计数器测量，不假定统一字符/Token比例。

配置面板应显示本次剩余预算、缓存复用、排队/暂停原因、实际与未知用量。旧预算未知时保守迁移，不授予额外额度；需要额外预算才明确请求授权，禁止无限自救。

## 9. Web与回执

状态至少区分：来源未定位、压缩源存在但未解码、有界扫描未完成、快照准备中、局部已审、全局待审、存在冲突、预算暂停、接受、过期。完整/局部/未知不能用同一个绿色完成标签。

详情提供：来源水位、输入类型/codec、分段覆盖数量、当前要求及其修正链、未覆盖项、全局审查范围、缓存和实际用量、当前配置/加载版本。选择任一缺口可定位对应原文；不能只给一个总进度百分比。

链路图的现有泳道继续使用，新增阶段作为相应情景摘要节点的内部阶段/详情，不再叠加第二张全图。所有节点/抽屉均使用同一回执源，不用总候选数猜送达量。新增状态默认英文、简体中文完整，其余支持语言使用已声明回退；原始用户文本不随UI语言擅自翻译。

## 10. 验收矩阵

| 情况 | 必须观察到的结果 |
| --- | --- |
| plain转zstd且内容不变 | 语义预算不重置；物理定位重新核验；未解码不报缺失 |
| 大文件/超长单条/损坏压缩帧 | 有界资源、明确partial/原因，无假完整和错误turn回退 |
| 中文/英文/混合emoji原句 | 精确条件及Unicode span可还原；否定/标点不因切片丢失 |
| 远距离“不是/不要/改成” | 真实后续用户来源支持替代；旧值保留历史而非现行 |
| 助手建议/完成声明 | 不进入用户约束，不证明成品或外部事实 |
| 同校不同项目/同cwd多会话 | 保留独立范围；缺少关联证明不得合并 |
| 后续仍未完成/子任务完成 | 全局未决保留，不因最后助手有回复而误标完成 |
| 分段全绿但交界未审 | 全局仍partial/unknown，不发布全覆盖accept |
| 尾部追加/旧消息修改 | 水位隔离；重审受影响分段、修正关联与全局状态 |
| 缓存/Provider/规范化变化 | 必要缓存失效但不重置原预算，不复用过期accept |
| 崩溃/并发重复执行 | 可续作、CAS防覆盖、同请求不重复结算 |
| 权限关闭/禁止写入/来源冲突 | 立即停止相应读取/写入，不借故恢复为普通缺失 |
| 预算耗尽/503或未知用量 | 有限停止、保留证据和原文路线，不无限重试 |
| full导航有未展开要求 | 显式未读与回读提示；不能声称所有条件已进入Agent上下文 |
| Web中英文与弹窗 | 状态/数量/来源一致，长内容可滚动，语言切换不改来源语义 |

验收以隔离夹具、已有真实来源重放及旧路径对照为主，不要求用户反复建新会话。模型质量指标须区分受控样本、真实任务、语义审稿与外部事实；任何百分比需公开分母、覆盖、失败及成本。

## 11. 自检与实施顺序

本设计没有按具体学校、某次失败ID或固定模型能力名单做规则。原文完整、元数据排除、范围、语义判断与形式覆盖各有独立证据，不互相替代；压缩源和持续增长源是正式输入类而非异常特例。

先验收已有链路修补与原预算恢复；再实现格式适配/快照、覆盖账本、分段与跨段审查、兼容读取、后台预算/断点、Web及真实回归。架构实现前需要审阅本文件，再据此形成逐项实施计划和最终验收门。当前未实现的新schema不会写入生产或改变旧信任契约。
